# 已知问题与设计决策

## 已知问题（均为体验层面，不影响可玩性与通关）

1. **视角旋转为 90° 步进**：`Q`/`E`（或 HUD ⟲⟳）平滑旋转，滚轮缩放（0.65x~1.8x）。不做自由环绕 —— 等距步进保持空间可读性，且俯仰角固定避免正交相机穿模。云海会随视角方位旋转，恒在背景侧。
2. **旋转中的乘坐体验**：旋转类机关（rotator）若角色站在静态对接点时启动，角色不会跟随旋转（防止把玩家意外甩到桥上）；只有明确站在机关节点上才会乘坐。升降/平移机关则始终连人带台。
3. **压力板为闩锁式**：触发后永久生效，不支持「踩住才保持」的瞬时机关。该简化使谜题状态空间可被 BFS 完整验证（保证所有关卡有解）。
4. **暂停时渲染继续**：暂停面板打开时 3D 画面仍在渲染（停止游戏逻辑与机关），背景为动态实景 —— 属于预期表现。
5. **移动端**：触屏点击移动可用（pointer 事件），但界面按钮尺寸按桌面优先设计，小屏布局未做深度适配。
6. **音频自动播放策略**：浏览器要求用户手势后才能出声 —— 首次点击页面任意处（如「开始游戏」）后音乐开始播放，属正常行为。
7. **多标签页共享存档**：进度存于 LocalStorage，同一浏览器的多个游戏标签页各自持内存状态，切换标签时可能互相覆写进度（单标签页游玩不受影响）。

## 设计决策记录

| 决策 | 理由 |
| --- | --- |
| **程序化几何替代 GLTF 资产** | 角色与建筑由参数化几何组合（`MeshDef` 数据驱动），零外部资源、秒加载、无版权风险。渲染层与数据层已解耦，未来可无痛替换为 GLB 资产（three/GLTFLoader 即插即用）。 |
| **端口重合连接规则** | 「看起来接上 = 真的能走」由同一几何规则保证；谜题全部由机关状态驱动，固定相机，不靠视角造假。 |
| **固定俯仰 + 90° 步进旋转视角** | 等距视角利于空间判断；连接规则按世界坐标计算，视角旋转不影响谜题，只改变观察角度。 |
| **闩锁式压力板** | 使游戏状态可被有限状态机完整建模 → BFS 可证明每关可通关（`npm run verify`）。 |
| **zustand 只存 UI 态** | 每帧游戏逻辑在 `LevelEngine`（纯 TS 类），避免 React 重渲染风暴。 |
| **LocalStorage 存档 v1** | 键 `gate-of-dreams:save:v1`，含版本号，未来格式升级可迁移。 |

## 资源与兼容性

- 目标浏览器：Chrome / Edge / Safari / Firefox 现代版本（WebGL2）。
- 最低分辨率建议 1024×640；更小屏幕可玩但界面按比例缩放。
- 构建产物为纯静态文件，无任何服务端依赖。
